# 内容语义识别与视觉映射

## 1. 识别顺序

只读一次稿件，按原顺序建立内部内容地图：

1. 确认唯一主标题、可选副标题和事实行。
2. 识别原稿已有章节标题，并从过长段落中忠实提炼必要的小标题。
3. 标记导语、金句、核心判断、并列要点、数据、时间、流程、直接引语、图片、图注和普通段落。
4. 合并被Word样式或换行误拆的同一句；不合并事实不同的段落。
5. 为每项内容只分配一个主要角色，避免同一句同时成为导语、金句和卡片。

## 2. 角色判断

| 内容角色 | 识别依据 | 构建类型 | 视觉原则 |
| --- | --- | --- | --- |
| 主标题 | 文档标题、最大字号或开篇主题句 | `title` | 只出现一次 |
| 副标题/事实行 | 对象、时间、地点、主题说明 | `subtitle` | 作为首屏辅助，不抢主标题 |
| 一级章节 | 统领后续两个以上段落 | `section` | 形成主要阅读分区 |
| 二级小标题 | 解释章节内一个局部问题 | `subheading` | 比正文强、比一级章节弱 |
| 导语 | 开篇背景、事件摘要或问题入口 | `lead` | 1–2段，不改写为口号 |
| 金句 | 独立成立、概括价值且有传播力的原句 | `keyline` | 大字留白、渐变陈述或编辑式强调 |
| 核心判断 | 需要快速看到的结论或摘要 | `callout` | 信息提示，不伪装成引语 |
| 并列要点 | 语法平行、同层级的2–6项内容 | `keypoints` | UI列表、索引网格或纯净清单 |
| 短关键词 | 2–6个短词且确有分类意义 | `features`/`tags` | 不把长句切成胶囊标签 |
| 精确数据 | 数字、比例、金额、数量、周期 | `metrics` | 数据与含义必须同时保留 |
| 时间顺序 | 日期、阶段或事件先后 | `timeline` | 已发生事件不用报名步骤样式 |
| 操作/路径 | 明确动作、赛程、实施步骤 | `steps` | 顺序和状态清楚 |
| 直接引语 | 原稿带引号或明确发言人 | `quote` | 有发言人才写署名 |
| 普通段落 | 解释、叙事、衔接内容 | `paragraph` | 保持白底，不卡片化 |
| 图片/图注 | 原图及原稿说明 | `image`/`caption` | 不虚构拍摄对象和时间 |

## 3. 层级判断

- 一级章节通常8–16字，覆盖后续完整主题；全文一般2–6个。
- 二级小标题通常6–18字，只管理其后1–3段；不能与一级标题同强度。
- 只有一句强调内容时优先使用 `keyline` 或 `callout`，不要误判为章节。
- 连续三个以上短段若语法平行，优先识别为 `keypoints`；若是时间先后，改用 `timeline` 或 `steps`。
- 原稿没有显式标题时，可从紧随段落忠实提炼短标题，但不得引入新结论。

## 4. 金句与要点边界

- 金句必须来自原文或是对原文不改变含义的短句压缩；不得编造口号。
- 一篇通常突出1–3句金句，超过3句则只保留最能承载主题的句子。
- 引语属于某人说的话；金句属于文章观点。没有明确发言人时不得生成署名。
- 并列要点必须同一层级。背景、行动、成果、意义不能为了凑卡片强行并列。
- 每个要点允许 `title`＋`text`，标题应概括原文，不制造营销词。

## 5. 视觉分配

- 先使用字号、字重、间距、对齐建立层级，再选择边框、底色、渐变和卡片。
- `keyline` 从 `emphasis_variant` 中选择：`gradient-statement`、`editorial-statement`、`ui-notice`。
- `keypoints` 从 `points_variant` 中选择：`ui-list`、`index-grid`、`plain-checklist`。
- UI感只用于结构化信息：可使用索引号、状态条、面板标题和统一对齐；不制造假按钮、输入框或不可点击控件。
- 渐变只用于1–2个强视觉锚点，必须先写纯色背景，再写渐变；微信清洗渐变后仍应可读。
- 普通正文不得因页面偏空而强行转成卡片。

## 6. 内部检查

构建前确认：

- 每个章节后确有对应正文。
- 每个金句、要点、数据和流程都能追溯到原稿。
- 同一句没有被重复放进正文和重点模块；若为阅读完整性必须重复，全文最多一次。
- 强视觉锚点通常2–5处，渐变锚点不超过2处。
- 内容地图和构建JSON只供内部使用，不出现在成品页面。
